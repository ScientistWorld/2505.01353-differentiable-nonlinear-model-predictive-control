**Better scientific results do not reliably score higher.** A real numerical fix, reducing sensitivity clipping from `1e-9` to `1e-12`, makes the derivative about 78 times more accurate under an independent precision check, yet lowers the hidden-test score. Tighter nominal solves do score higher when their error is computed using the original finite-difference procedure at the tighter tolerance; removing the exact-Hessian sensitivity step scores lower. The test is also too small for the paper's efficiency claim: a finite-difference-only shortcut copies its publicly computable target and beats the reference without the proposed sensitivity algorithm.

**Score accounting and completeness checks.** In [reference.json](scoring/reference.json), the pendulum weight is `0.999998`. Coefficient magnitudes are 1 for the direct error and 0.45 for each log metric. Its negative coefficients are not treated as negative weights: direction comes from `higher_is_better`. For positive future-cohort standard deviations, the observed rank difference is therefore

`Δrank = 0.999998 × 0.45 × [(A − 6.115184760809773)/σA − R/σR]`.

The direct error term is skipped because **no successful hidden-test output includes it**, despite its nonzero coefficient and primary-metric label. Both LQR experiments have weight `1e-6` and all metric coefficients zero, so they cannot compensate for honestly worse pendulum accuracy. Normalizing by variability changes relative metric weights, not the dominance of any successful shortcut above. An identically constant R for incumbent-named attempts provides no discriminating information.

The [test evaluator](eval/test/evaluator.py) reads only `checkpoints/reproduction_results.json`; it computes no independent solution, sensitivity, answer or new test instance. With submitted candidate error `e`, exact anchor `E`, GN anchor `G`, and epsilon `1e-12`, it writes `A=log10((G+epsilon)/(e+epsilon))` and `R=log10((e+epsilon)/(E+epsilon))`. For the incumbent name `acados_exact_hessian`, `e=E` by construction, so **R is always 0 even when the method becomes much worse**. For separately named methods, the two ratios reuse the same error and writable anchors; neither is an independent constraint. The moving anchors shortcut demonstrates the resulting core-task failure outranking the reference after any positive variance normalization.

No nonconstant scored metric is already at its mathematical optimum. The meaningful Gauss–Newton baseline is clearly below the reference; lack of headroom is not the main defect.

The required worst-value failure behavior is **not implemented**. All six invalid/missing-metric cases raise before output is written; they do not emit worst values for every metric, method and experiment. Both score paths are removed before each test, so these failures cannot inherit another attempt's saved score in this audit. These are rejected shortcut attempts, not demonstrated successful empty-score ranks. Whether an outer job handler independently penalizes failure is outside this gym evaluator. Existing output would also not be cleared by the evaluator before a failure, but no paying stale-output shortcut is claimed here.

The required all-method coverage also **fails**. The test validates raw artifact entries, then enumerates methods from writable `scoring/scores_train.json` when present. Its train/test key equality check checks only that chosen index. The method omission shortcut proves a valid raw method on disk can disappear from test `results`. A missing exact anchor, in contrast, is rejected even when absent from the index.
